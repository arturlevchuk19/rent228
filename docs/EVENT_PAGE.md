# Страница мероприятия

Ветка: `feature/event-project-page`.

Открытие из списка и календаря ведёт на отдельную страницу внутри обычной компоновки приложения. Адрес содержит `?event=<id>`; новое мероприятие — `?event=new`. Ссылка работает при обновлении страницы. Кнопка «Назад» и история браузера возвращают пользователя в исходный раздел. Фильтры, выбранный месяц и прокрутка списка сохраняются. При уходе с несохранёнными данными требуется подтверждение.

## Сохранённые возможности

Все прежние поля находятся в блоке «Данные мероприятия»: даты, включая приблизительные, название, тип, заказчик, площадка, старший на площадке, статус, прогресс и примечания. Составление и копирование сметы, договор, спецификация, сохранение и отмена доступны на новой странице. Базовые поля также можно менять в верхней части. Старший на площадке расположен непосредственно под датой и статусом.

PDF в верхней панели экспортирует сохранённую смету. Изменённые данные мероприятия сначала нужно сохранить.

## Новые блоки

- Сметы мероприятия: действующая смета и её прежние действия.
- Оборудование: позиции текущей сметы и переход в спецификацию, где доступен ручной добор.
- Тайминг: пункты по датам мероприятия; разрешено ночное время, например 21:00–03:00.
- Описание: заголовки `#`, жирный текст `**...**`, списки `-` и выделение `==...==`. HTML не исполняется.
- Люди: назначения из сметы плюс вручную добавленные участники, группы и ставки в BYN. Назначения из сметы изменяются через её редактор.
- Транспорт: автомобиль, водитель и примечания.
- Звук, свет, медиа, Input / Output: технические заметки.

Красным зачёркнутые блоки референса не добавлены. Примерные данные референса не загружаются в рабочую базу. Для мероприятия используется существующая смета; модель нескольких смет на мероприятие не вводится.

## Миграция

Перед сохранением новых блоков выполните файл `supabase/migrations/20261027000000_event_project_details.sql` в SQL Editor Supabase. Он добавляет `events.project_details` (JSONB) и проверку типа объекта. Существующие данные не удаляются, права на запись остаются правами редактирования мероприятий.

Пока миграция не установлена, прежние поля продолжают сохраняться. Попытка сохранить новые блоки покажет сообщение об установке миграции; введённые данные остаются на странице.

## Проверки

- `npm run typecheck`
- `npm run test:event-project`
- `npm run test:account`
- `npm run build`

Проверено в Chromium при ширине 375 и 1440 px на тестовых HTTP-ответах: прямая ссылка, размещение в main, наличие блоков, сохранение, возврат и восстановление прокрутки, подтверждение несохранённых изменений, отсутствие горизонтального переполнения и ошибок браузера. Производственные данные не изменялись.

# Личный кабинет и настраиваемые права

В интерфейсе: значок профиля → «Личный кабинет». Вкладки: «Профиль», «Пользователи», «Роли и доступ». Подписки нет.

## Установка в рабочем Supabase

1. В SQL Editor выполните **весь** файл `supabase/migrations/20261026020000_account_and_role_access.sql`. Он добавляет роли, проверяемые операции профиля и политики доступа. Данные мероприятий и оборудования не удаляются. Владельцы (`superuser`) сохраняют полный доступ. Сотрудникам назначаются исходные права согласно их роли; они перечислены в начале SQL.
2. В Supabase Dashboard → Edge Functions создайте функцию **account-admin**, замените её код содержимым `supabase/functions/account-admin/index.ts` и опубликуйте. Отключите проверку JWT в настройках шлюза этой функции: код функции самостоятельно проверяет bearer-токен через Supabase Auth при каждом запросе. Секрет `SUPABASE_SERVICE_ROLE_KEY` доступен в Edge Functions автоматически; не добавляйте его во фронтенд.

   Через CLI вместо Dashboard:
   ```sh
   supabase functions deploy account-admin --project-ref YOUR_PROJECT_REF --no-verify-jwt
   ```
3. Обновите сайт и заново откройте личный кабинет.

Смена e-mail подтверждается средствами Supabase Auth. Настройки отправки писем должны быть настроены в проекте. Пока новый адрес не подтверждён, логин остаётся прежним.

## Роли

- `superuser` — Владелец
- `admin` — Администратор
- `foreman` — Старший по площадке
- `clerk` — Менеджер
- `staff` — Техник
- `warehouse` — Кладовщик

Названия и права существующих ролей изменяются во вкладке «Роли и доступ». Выбранный доступ включает предыдущие уровни: просмотр → редактирование и добавление → удаление. Владельца менять нельзя. Свои права и статус нельзя изменять через список пользователей. Управлять можно только пользователями ниже себя и без прав выше собственных. Новые учётные записи создаются сервером без переключения текущего сеанса.

Удаление пользователя с зависимыми документами отклоняется: используйте «Отключить», чтобы сохранить историю. Отключённые пользователи не получают доступ к рабочим таблицам. Изменения прав применяются в базе сразу, в открытом интерфейсе — после возвращения фокуса на вкладку или обновления.

## Проверка установки

- Владелец видит все разделы и список пользователей.
- Создайте тестового «Техника», войдите им в другом браузере.
- Дайте роли только просмотр оборудования: добавление, изменение и удаление недоступны.
- Измените уровень на «Редактирование»: добавление и изменение доступны, удаление — нет.
- «Удаление» добавляет право удаления. Данные также защищаются политиками Supabase, а не только кнопками.
- Проверьте смену имени, смену пароля с неверным и верным текущим паролем, отключение тестового аккаунта.

SQL и Edge Function подготовлены в репозитории; публикация frontend в main не применяет их автоматически.
